### 순서 결정 (orderForRuns)

- 전부 페이지 있음
  # 저장 순서가 원본과 어긋나 있어도 페이지 순으로 바로 세운다.
  입력: A(3) B(1) C(2)
  결과: B C A

- 전부 페이지 없음 (옛 데이터)
  # 물려받을 값이 모두 같아져 저장 배열 순서가 그대로 남는다. 이게 옛 데이터 폴백이다.
  입력: A(-) B(-) C(-)
  결과: A B C

- 페이지 정보 섞임
  # 아는 것끼리는 페이지 순, 모르는 것은 저장 순서상 직전 문제 바로 뒤에 붙는다.
  입력: A(1) B(-) C(3) D(-) E(2)
  결과: A B E C D

- 같은 페이지에 여러 문제
  # 한 쪽에 여러 문제가 있으면 저장 순서를 흔들지 않는다.
  입력: A(5) B(5) C(5)
  결과: A B C

- 넓은 청크 뒤에 페이지 모르는 문제
  # pageTo까지 물려받지 않으면 B가 (10,10)이 되어 정작 자기 앞의 A(10~15)를 제치고 나선다. 기대값이 A B C인 것이 그 방지책이 살아 있다는 뜻이다.
  입력: A(10~15) B(-) C(12)
  결과: A B C

- 맨 앞이 페이지 모르는 문제
  # 물려받을 앞 문제가 없으면 0쪽으로 두어 저장 순서 맨 앞자리를 지킨다.
  입력: A(-) B(-) C(5)
  결과: A B C
