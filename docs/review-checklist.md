# LawPass 코드 리뷰 체크리스트

구현 워크스페이스가 작업한 브랜치를 merge하기 전에, 이 파일을 기준으로 검토 워크스페이스(별도 Claude Code 세션)에서 diff를 확인합니다.

## 사용법

검토 워크스페이스에서:

```
이 파일(docs/review-checklist.md) 기준으로 git diff main..<브랜치명> 을 검토해줘.
```

## 체크리스트

1. **범위** — 요청받은 파일/로직만 건드렸는가? 관련 없는 파일이 diff에 섞여 있으면 왜 필요한지 근거를 대야 한다. 근거 없으면 스코프 밖으로 판단.

2. **회귀** — 이미 검증되어 있는 아래 항목들이 이번 변경으로 깨지지 않았는가?
   - 관리자 전용 게이트 (`isAdmin`, UI 노출 + 함수 내부 이중 체크)
   - 이미지 첨부의 동기화 큐 분리 (`sync.ts`의 `ListName`에 `questionImages`가 들어가면 안 됨 — 개별 write/lazy read 유지)
   - `passage-table.tsx`의 rowspan/colspan 레이아웃 로직 (`lib/tableGrid.ts`)
   - `progressQuestions()` 기반 통합 진도표 카운팅 (관리자/일반 사용자 역할 분기 없이 내 문제 + 공유 문제집)
   - `saveQuestions()`의 `poolId` 필터링 (공유 문제집 중복 카운트 방지)

3. **빌드/타입체크** — `npx tsc --noEmit`, `npm run build` 둘 다 통과하는가? 로그를 실제로 보여줬는가, 아니면 "통과했다"고 주장만 했는가?

4. **주장 검증** — 보고서의 "확인했다/검증했다"는 문장마다, 실제로 재현 가능한 근거(before/after diff, 실행 로그, 실제 테스트 케이스)가 붙어 있는가? 근거 없는 주장은 신뢰하지 말고 직접 diff에서 확인.

5. **Firestore 영향** — 새 경로/컬렉션이 생겼다면 `firestore.rules`에 실제로 커버되는지 (`{document=**}` 와일드카드에 기대는 경우, 실제로 그 규칙이 존재하는지 확인) — schema 변경이 기존 shard 동기화(700KB 한도)에 영향 주는지.

6. **잔여물** — 테스트용으로 만든 임시 하네스/스크립트가 지워졌는가? 불필요한 백업 파일이 커밋에 섞여 있지 않은가?

7. **커밋 위생** — main 기준으로 브랜치를 땄는가? 커밋 메시지가 "왜"를 설명하는가?

## 결과 보고 형식

문제 있으면: 파일/줄 번호 + 구체적으로 무엇이 왜 문제인지.
문제 없으면: "문제없음"이라고만 답하고 장황하게 설명하지 않는다.
